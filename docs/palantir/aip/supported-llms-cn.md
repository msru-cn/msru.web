## 支持的 LLM

Palantir AIP 支持来自领先提供商（包括 xAI、OpenAI、Anthropic、Meta 和 Google）的各种 LLM（大语言模型）和文本嵌入模型。支持的模型列在本页，可在 Palantir 平台中用于驱动 AIP 工作流，但[可用性](https://www.palantir.com/docs/foundry/aip/supported-llms/#llm-availability-prerequisites)可能因 enrollment 而异（例如因[地理限制](https://www.palantir.com/docs/foundry/aip/supported-llms/#llm-availability-by-geography)）。

要使用特定模型，enrollment administrator 必须先通过 Control Panel 启用该模型系列。了解如何[配置 enrollment 上可用的 LLM 选择](https://www.palantir.com/docs/foundry/aip/enable-aip-features/#enable-llms)。

## 可用音频模型

Palantir AIP 支持两类音频模型：用于构建对话式语音应用的实时 speech-to-speech 模型，以及用于将音频转换为文本的转录模型。要了解如何从以 Foundry 用户身份认证的浏览器应用中使用音频模型，请参阅[构建语音启用的 OSDK 应用](https://www.palantir.com/docs/foundry/realtime-audio/build-a-voice-enabled-osdk-application/)。有关 Foundry 上音频的高层概述，请参阅[实时音频](https://www.palantir.com/docs/foundry/realtime-audio/overview/)。

**Mode** 列指示每个模型支持的使用路径：

*   **Realtime：** 流式双向 WebSocket。模型处理语音活动检测、轮流发言和流式输出；应用在捕获原始音频时即时发送。
*   **Static：** 请求-响应 HTTP。应用发送有限音频负载并接收转录结果。适合转录预先录制的音频文件。如果应用自行执行音频分块，也可用于实时转录——这是一种以增加应用复杂度换取更低更可预测的每分钟成本的权衡。当实时模型在你的 enrollment 上不可用时，这种方法也有帮助。延迟取决于分块大小和模型，因此请针对你的用例进行评估。

### 实时 speech-to-speech

实时 speech-to-speech 模型接受流式音频输入，在对话过程中进行工具调用，并通过 WebSocket 连接返回流式音频输出。

| 模型 | API 名称 | 提供商 | 模式 |
| --- | --- | --- | --- |
| [GPT Realtime 1.5 ↗](https://developers.openai.com/api/docs/models/gpt-realtime-1.5) | `gpt-realtime-1.5` | OpenAI Direct, Azure OpenAI | Realtime |
| [GPT Realtime 2.0 ↗](https://developers.openai.com/api/docs/models/gpt-realtime-2) | `gpt-realtime-2` | OpenAI Direct | Realtime |

### 转录

转录模型将音频转换为文本。大多数同时支持实时（流式 WebSocket）和静态（请求-响应 HTTP）模式；`Whisper_large_v3` 是 Palantir 托管的，仅支持静态模式。

| 模型 | API 名称 | 提供商 | 模式 |
| --- | --- | --- | --- |
| [Whisper 1 ↗](https://platform.openai.com/docs/models/whisper-1) | `whisper-1` | OpenAI Direct, Azure OpenAI | Realtime, Static |
| [GPT-4o Transcribe ↗](https://platform.openai.com/docs/models/gpt-4o-transcribe) | `gpt-4o-transcribe` | OpenAI Direct, Azure OpenAI | Realtime, Static |
| [GPT-4o Mini Transcribe ↗](https://platform.openai.com/docs/models/gpt-4o-mini-transcribe) | `gpt-4o-mini-transcribe` | OpenAI Direct, Azure OpenAI | Realtime, Static |
| [GPT-4o Transcribe Diarize ↗](https://platform.openai.com/docs/models/gpt-4o-transcribe-diarize) | `gpt-4o-transcribe-diarize` | OpenAI Direct, Azure OpenAI | Realtime, Static |
| [Whisper Large V3 ↗](https://huggingface.co/openai/whisper-large-v3) | `Whisper_large_v3` | Palantir 托管 | Static |

当需要对多说话人音频（如会议）进行说话人分离时使用 `gpt-4o-transcribe-diarize`。对于不需要说话人分离的通用转录，根据适合你用例的质量、成本和延迟权衡选择 `gpt-4o-transcribe`、`gpt-4o-mini-transcribe` 或 `whisper-1`。在 OpenAI Direct 或 Azure OpenAI 集成不可用的环境中使用 `Whisper_large_v3`。

有关各区域的 enrollment 可用性，请参阅下方 [LLM 地理可用性](https://www.palantir.com/docs/foundry/aip/supported-llms/#llm-availability-by-geography)表格。

## LLM 可用性前提条件

AIP 是模型无关的，支持多种 LLM 驱动用例的模型选择；更多信息请参阅[此 AIP 中所有可用模型的列表](https://www.palantir.com/docs/foundry/aip/supported-llms/#llm-availability-by-geography)。

但 LLM 的选择和可用性因 enrollment 而异，取决于特定模型在 enrollment 上可用的某些前提条件。这些前提条件决定了模型系列在 Control Panel 中显示为 **enabled**、**disabled** 还是 **disallowed**。了解更多关于 [Model enablement 界面中的模型状态](https://www.palantir.com/docs/foundry/aip/enable-aip-features/#understanding-model-states)。

条件如下：

*   **模型已集成到 AIP：** Palantir 致力于支持行业最新的旗舰模型，并正在积极开发与模型发布和更新同步的支持。
*   **已在需要时提供法律确认：** Enrollment administrator 必须接受提供商的法律要求和使用条款才能启用某些模型。这通常可以在 Control Panel 的 **Model enablement** 标签下完成。等待法律确认的模型显示为 **disabled** 状态。
*   **AIP 已在 enrollment 上启用以使用 LLM：** 要在 AIP Logic、Transforms、Functions 和 Pipeline Builder 等产品中使用，必须为目标用户组启用自定义工作流的 AIP 能力权限。
*   **区域可用性兼容（针对外部提供商模型）：** 对于 GPT、Claude 和 Gemini 等模型，如果你的 enrollment 有地理限制，可能需要考虑区域可用性。例如，GPT4o 和 Claude 3 Sonnet 在发布时仅在美国可用，之后才扩展到 EU、UK 和其他区域。详情请查阅[模型地理限制部分](https://www.palantir.com/docs/foundry/aip/supported-llms/#llm-availability-by-geography)。因地理限制而不可用的模型显示为 **disallowed** 状态。
*   **已进行额外审查（针对某些 Palantir 提供的模型）：** 开源模型如 Llama 和 Mixtral 可能需要额外的 Palantir 工程审查来支持你的环境。需要这些审查的模型显示为 **disallowed** 状态。
*   **与特定 AIP 前端产品的集成时间：** 新 LLM 需要时间才能被所有 AIP 产品完全支持（例如在 AIP Logic 和 Pipeline Builder 的 Use LLM 节点功能中）。
*   **风险考量（针对实验性模型）：** 由于实验性模型可能会中断或需要手动迁移到更新的模型，我们限制其推出，客户可能需要在启用使用前确认。"实验性"一词由模型提供商定义，不适用于生产用途。

### LLM 地理可用性

某些 enrollment 可能因地理限制（简称 georestriction）而只能访问有限的模型集；某个区域的地理限制意味着该区域的所有 AIP 对 LLM 的请求都停留在该区域范围内。例如，如果 enrollment 定义为 EU 地理限制，所有 LLM 请求将在 EU 处理。非地理限制的 enrollment 可以访问 Palantir 支持的完整模型集。

## 接入自有模型 (LLM)

Bring your own model 是一项为客户提供一等公民级支持的能力，让你可以将自有 LLM 或账户接入 AIP，与所有 Palantir 开发者产品配合使用——AIP Logic、Pipeline Builder、Chatbot Studio、Workshop 等。

查阅 [bring your own model](https://www.palantir.com/docs/foundry/aip/bring-your-own-model/) 文档了解如何注册模型以供 AIP 使用。

# [](https://www.palantir.com/docs/foundry/action-types/set-up-webhook/#set-up-a-webhook)Set up a webhook

## [](https://www.palantir.com/docs/foundry/action-types/set-up-webhook/#prerequisites)Prerequisites

1.   Complete the [getting started](https://www.palantir.com/docs/foundry/action-types/getting-started/) tutorial to learn about how to set up a basic action.
2.   Set up a [webhook](https://www.palantir.com/docs/foundry/data-connection/webhooks-setup/) to create a connection to an external system. You may need to work with a system administrator who has permissions to connect to source systems before creating a webhook.

## [](https://www.palantir.com/docs/foundry/action-types/set-up-webhook/#steps)Steps

In the below example, suppose that we have a webhook called **Modify ticket priority** which accepts a `priority` string value and sends it to an external system.

Navigate to your action, select the **Logic** tab, select **Add new rule**, then select **Webhook**.

![Image 7: Add new webhook](https://www.palantir.com/docs/resources/foundry/action-types/webhooks-add-new-rule-webhook.png?width=600)
By default, the newly added webhook is configured as a **side effect**; this makes the webhook run _after_ objects are edited in Foundry. Alternatively, select **Writeback** to have the webhook run _before_ object edits.

![Image 8: Select writeback or side effect](https://www.palantir.com/docs/resources/foundry/action-types/webhooks-select-writeback-or-side-effect.png?width=400)
In the menu below, select the webhook you want to execute. In this example, we select the **Modify ticket priority** webhook. If you wish, you can select a different version of the webhook.

![Image 9: Select webhook to execute](https://www.palantir.com/docs/resources/foundry/action-types/webhooks-select-webhook-to-execute.png?width=400)
Next, configure webhook input parameters based on action parameters. By default, a new action parameter is generated for each webhook input unless an existing action parameter with the same name already exists, in which case the existing parameter is automatically configured. In this example, we map the webhook input called `priority` to an existing action parameter called `Ticket Priority`.

![Image 10: Mapping webhook input to an existing action parameter](https://www.palantir.com/docs/resources/foundry/action-types/webhooks-input-mapping-example.png?width=400)
Select **Add webhook** to complete adding the webhook rule to your action. Note that after the webhook is added, the Rules section shows that the writeback will occur before objects are modified.

![Image 11: Add new webhook (completed)](https://www.palantir.com/docs/resources/foundry/action-types/webhooks-add-webhook-complete.png?width=600)
You may want to remove any autogenerated parameters created when you added the webhook which are now unused.

![Image 12: Remove autogenerated parameters](https://www.palantir.com/docs/resources/foundry/action-types/webhooks-remove-autogenerated-parameters.png?width=600)
Select **Save** in the top-right to save your changes to the action. Now, when the action is applied, the request to the external system will be made before any changes are applied to objects in Foundry.

## [](https://www.palantir.com/docs/foundry/action-types/set-up-webhook/#next-steps)Next steps

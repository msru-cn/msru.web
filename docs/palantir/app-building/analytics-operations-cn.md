# 将分析连接到运营

虽然 Foundry 的重点是支持 [operational workflows](https://www.palantir.com/docs/foundry/app-building/operational-apps/) 将数据回写到系统中，但使用 Foundry 的 [analytical capabilities](https://www.palantir.com/docs/foundry/analytics/overview/) 所得到的结果同样关键。本页介绍如何将分析工具以统一的方式交付给终端用户，赋能决策。

## 仪表板

在 Ontology 中对数据进行开放式探索，往往能产生对组织内其他人有用的洞察。从一组对象出发，下钻到子集，用图表或关联对象探索属性，可能形成一个可复用的工作流，并以有价值的方式与其他平台能力结合。

[Quiver](https://www.palantir.com/docs/foundry/quiver/overview/) 是 Foundry 中用于对对象数据进行开放式分析的应用。Quiver 仪表板支持创建参数化、精选视图，让终端用户以结构化方式探索数据。发布仪表板后，你可以通过几种不同方式在运营应用中使用它：

*   Quiver 仪表板可以 [embedded into Workshop applications](https://www.palantir.com/docs/foundry/quiver/dashboards-workshop/)，在结构化工作流中灵活地向用户展示仪表板。
*   Quiver 仪表板可以嵌入 [Carbon](https://www.palantir.com/docs/foundry/quiver/dashboards-carbon/)，用户可以在工作区中以标签页形式访问模板。

利用这些功能，探索性分析可以快速从临时仪表板或洞察转变为运营工作流的核心部分。

## 模型

Foundry 的 [machine learning](https://www.palantir.com/docs/foundry/model-integration/overview/) 能力提供了一整套模型开发、集成、评估和部署工具。模型按照组织标准验证通过后，可以轻松部署给终端用户。

Workshop 对 [Scenarios](https://www.palantir.com/docs/foundry/workshop/scenarios-overview/) 的支持让机器学习可以直接部署给终端用户，无需自定义开发或大量配置。用户操作他们熟悉的概念，同时以易懂的形式（如 _forecast_ 或 _estimate_）查看模型支持的结果。

关于将机器学习与组织成果结合的更多细节，参见 [Models in the Ontology](https://www.palantir.com/docs/foundry/ontology/models/)。

## Turbo: 一切指令极速执行的核心中枢网络引擎

传统利用简单的 NPM Script 在根目录使用 `cd xxx && npm run dev` 或串行顺序构建的方法，在此庞大体量前必然面临极度阻滞等待耗时的问题！
我们引入并打通了原生的 Turbo 并发管道及无级缓存（Cache Hit）调度：

```bash
# 全局唤醒所有的应用一起进入热备及底盘包级联监控侦听热更新开发状态
# 底漆加持 Turbopack 后端编译器技术支持着这种几十个庞大的 React SSR 微项目能同秒级加载出屏的核心实力！
pnpm dev

# 如果你只想精巧地在不相关的功能模块旁修改部分样式，并只打拉起对应包节省全盘内存开支：
pnpm dev --filter web
```

在执行 `pnpm build` 时，这个网络引擎甚至能在发版流转管道内跳回计算所有相关层级包散列的文件哈希（Hash Map），若你在一周前打包部署的卡片包 `@msru/ui...` 源文件到今天并没有丝毫位移改变，它会智能且疯狂跳过滤掉那些漫长的再编译进度条，直取底盘超快级缓存！让你 1 小时的痛苦集成缩短倒数成 5 秒。

## Biome: 最冷血的新时代格式扫描怪兽

因为陈腐迟钝且低俗运行极其缓慢笨重的 Prettier 加 ESLint 的传统方案架构缝合会导致极其恼怒的高消耗卡顿体验。
于是我们在全局系统 `biome.json` 环境里，接入了这个一栈包打天下、由 Rust 底层极高效率引擎全栈重构的新型系统代码质量纠察队—— [Biome](https://biomejs.dev/) 作为守护神探针。

**核心监控准则防线**：
- **铁血瞬扫与规范修正机制**：变量没使用立刻拦截；多余无意义的大括号分号、单引号双引号不完全一致立刻重重敲打纠正！甚至当你使用 Tailwind `className="..."` 撰写类名没有经过科学计算排列时依然会极速干预！
- **平滑且隐秘的免疫规则覆盖下推（Zero-Config for apps）**：针对最近引入的新版概念（如 Tailwind-v4 里极端的 `@source` 与诡异主题语法体系），原生 AST 会将其指为“坏语法包”拒收报错。对此一切相关的系统重编规则完全隔离在 `packages/biome-config/` 当中！对于所有开发业务的程序员来说环境都是透明清爽的顺畅体感，不用关心复杂指令兼容。

## Lefthook: 最终 Git 高门槛安检门神防线阻断链

就算在本地跑顺了，一旦进入 `Commit` 生命防线轨道，隐藏在系统根盘之下的 `lefthook.yml` 将无差别并且无条件接管甚至拦截 Git 命令体系进行强有校验与制裁截留！不达全项合规要求的人连推上去的资格都没有！

### 第一层防灾网卡：Pre-commit 代码检查拦截
你执行 `git commit -m ...` 意图打包保存提交上库？
抱歉，门神此时强制阻断！钩子将被全屏启动触发激活下底基座 Biome 极速静态安检仪器。就算你仅仅是一个括号的格式层级多打了若干极其微弱的几层回车留白空档间隙，这套预留的规则探测逻辑也会进行**惨无人道且不留情面的无情驳回阻止打包行为！！**。

### 第二层纪律追踪卡：Commit-msg 必须基于强约束追踪指引
不仅推上去的内容文件要绝对干净合规化！我们更是从骨髓层面上强制要求、约定了每一只单条提交留言附加信也必须遵循 `Conventional Commits` 约束体系（规范性的附文标识）。

- 当程序员写出例如：`update`、`fix`、`gogogo`、`修改了卡片的严重样式Bug及颜色` 这种严重随心所欲，使得事后代码无法由工具极速检索与定位历史流水的附文记录时......
- 这道网关引擎识别直接暴力把此提交流阻住驳回丢弃粉碎，甚至会在终端控制台警告。

**合法正确地留下历史的示范应为：**
- `feat(ui): 增加新的卡片复合型容器组件底座模板`
- `fix(auth): 修补了用户退出清理 Session 时极大概率产生残留指针丢失崩溃异常的问题`

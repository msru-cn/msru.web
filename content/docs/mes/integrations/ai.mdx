# AI 集成：从感知制造到自进化制造

在传统的 MES 架构中，系统扮演的是“记录员（Record Keeper）”的角色；而在 MSRU 体系中，MES 演进为了“智囊团（Cognitive Assistant）”。通过原生集成的大模型（LLM）能力与工业深度学习算法，我们将制造执行从“数字化”推向了“智能化”的深水区。

本指南将介绍如何配置并调用 MSRU | MES 的 AI 三大核心模块。

<Callout type="info" title="边缘侧推理引擎">
  为了保证生产闭环的实时性，MSRU 的 AI 推理并不完全依赖中心云。我们在边缘 Agent 中集成了 **NPU 加速支持**，能够在 5ms 内完成对缺陷图片的识别或对振动波形的推理。
</Callout>

## 2. 预测性维护的技术实现 (RUL 模型)

预测的核心在于处理非线性的时序数据。MSRU 边缘节点会实时采集 PLC 发出的高频电流、温度与振动信号。

<Tabs items={['算法推导', '代码配置', '监测看板']}>
  <Tab value="算法推导">
    ### 威布尔分布 (Weibull Distribution) 与健康得分
    系统基于历史失效数据，动态计算当前设备的健康得分 $\mathcal{H}(t)$。当得分低于阈值 $\alpha$ 时，会自动触发维保工单。
    <MathEquation 
      inline={false} 
      formula={String.raw`R(t) = e^{-(t/\eta)^\beta} \implies \mathcal{H}(t) = \frac{1}{1 + \exp(-\lambda(R(t) - \theta))}`} 
    />
  </Tab>
  <Tab value="代码配置">
    ```json showLineNumbers
    {
      "model": "MSRU-RUL-TRANSFORMER-V1",
      "inputs": ["current_ma", "vibration_hz", "temp_c"],
      "threshold": 0.85,
      "on_alert": {
        "action": "AUTO_GENERATE_MAINTENANCE_ORDER",
        "priority": "HIGH"
      }
    }
    ```
  </Tab>
  <Tab value="监测看板">
    AI 引擎不仅输出“是否损坏”，还会给出 **置信度百分比** 及 **根因热力图 (SHAP Value)**，协助维修人员定位是轴承过热还是缺油。
  </Tab>
</Tabs>

## 3. 智能排产与强化学习

在生产订单频繁插单、物料供应不稳定的离散制造中，人工排产已成为效率瓶颈。MSRU | MES 集成了基于强化学习的调度模型。

<Steps>
  <Step>
    ### 环境建模
    将工位作为 Agent，将交期延迟（Tardiness）与切换成本（Changeover Cost）作为负向奖励函数（Penalty）。
  </Step>
  <Step>
    ### 模型在线演进
    利用每天真实的报工数据对模型进行微调（Fine-tuning）。系统会学习到：“在湿度高于 80% 的周二下午，[LANE-03] 的粘胶工序效率通常会降低 10%”。
  </Step>
  <Step>
    ### 一键重新排程
    当发生突发停机时，点击“AI 优化”，系统会在 10 秒内计算出影响最小的 5 套替代方案供生产主管选择。
  </Step>
</Steps>

## 5. 常见问题：AI 引入的“生产不确定性”

<Accordions>
  <Accordion title="AI 给出的质量判定错误怎么办？">
    MSRU 遵循 **“人机协同 (Human-in-the-loop)”** 原则。所有 AI 标记的缺陷均支持“人工纠偏”。当质检员修改判定后，该数据会自动标记为 `Correction_Training_Set`，在系统下一次凌晨更新时用于在线学习。
  </Accordion>
  <Accordion title="部署 AI 集成是否由于数据量大而拖慢 MES 响应？">
    不会。MSRU 采用 **计算卸载（Computation Offloading）** 技术。实时的报工逻辑在主线程，AI 推断在独立的协程或 NPU 核心运行。即使 AI 引擎因资源耗尽崩溃，基础的报工与追溯逻辑依然保持 100% 可用。
  </Accordion>
</Accordions>

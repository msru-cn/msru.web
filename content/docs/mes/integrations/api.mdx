# API 参考：工业级服务编排与系统集成

对于现代数字化工厂而言，MES 绝不应当是一座隔离的“信息孤岛”。MSRU | MES 的设计初衷是 **“API 第一 (API-First)”**，我们提供了覆盖全业务生命周期的开放接口，旨在支持企业轻松将生产数据接入 ERP、WMS 或自定义的 BI 大屏中。

本页面将详细说明如何通过安全、高性能的方式与 MSRU | MES 进行深度系统级集成。

<Callout type="warn" title="频率控制与背压保护">
  为了保证生产数据的实时性，我们的 API 设有智能背压控制。对于来自 ERP 的非实时大批量同步请求，请务必使用 `bulk_upload` 异步接口，以避免占用边缘节点的强实时计算资源。
</Callout>

---

## 1. 认证与安全：基于零信任的 mTLS

在工业环境中，传统的 Token 认证往往不足以应对复杂的内网安全需求。MSRU 建议采用 **设备侧 mTLS + 应用侧 OAuth2** 的双重验证体系。

<Tabs items={['认证流程', '请求示例']}>
  <Tab value="认证流程">
    1.  **Identity Registry**: 集成系统需在 MSRU Portal 注册并获取 `client_id` 与加密证书。
    2.  **Handshake**: 客户端发起 mTLS 握手，交换公钥。
    3.  **Token Issuance**: 通过证书签名换取具有强时效性的 Bearer Token。
  </Tab>
  <Tab value="请求示例">
    ```bash showLineNumbers
    curl -X GET "https://api.msru.sh/v1/workorder/list" \
      -H "Authorization: Bearer <ID_TOKEN>" \
      -H "X-MSRU-Tenant-ID: T-Factory-01" \
      --cert ./client.crt \
      --key ./client.key
    ```
  </Tab>
</Tabs>

## 3. 异步报工与状态回传：Webhook 机制

当产线发生关键事件（如：首件合格、设备急停、工单超期）时，MSRU 能够主动向订阅系统推送通知，减少轮询造成的资源浪费。

<Steps>
  <Step>
    ### 配置侦听端点
    在 [设置 > 集成] 中配置您的 Webhook URL（如 `https://erp.company.com/webhook/mes`）。
  </Step>
  <Step>
    ### 订阅事件类型
    选择 `ORDER_FINISHED`（工单完工）与 `QUALITY_ABNORMAL`（质量异常）事件。
  </Step>
  <Step>
    ### 处理签名校验
    MSRU 会在 Header 中附带 `X-MSRU-Signature`，请使用 Shared Secret 的 HMAC-SHA256 算法验证数据的完整性。
  </Step>
</Steps>

## 5. 性能估算：计算集成延迟

在大规模并发环境下，我们需要预估 API 的处理能力。

<MathEquation 
  inline={false} 
  formula={String.raw`T_{API\_Response} = T_{proxy} + T_{Auth\_Verify} + \underbrace{T_{Edge\_Pull}}_{\text{Optional Cache Hit}} + T_{Query}`} 
/>

由于 MSRU 的边缘缓存机制，针对“当前在线工单”的查询响应通常在 **50ms** 以内；针对“三年前历史档案”的冷数据检索可能由于需要从对象存储解冻而增加至 **200-500ms**。

# 集群备份与灾难恢复

「没有备份的基础设施等于没有基础设施。」本文档覆盖 K3s 集群的备份策略、自动化快照和灾难恢复流程。

---

## 备份范围

| 备份对象 | 位置 | 重要性 | 恢复难度 |
|---------|------|--------|---------|
| etcd 数据 | `/var/lib/rancher/k3s/server/db/` | 🔴 致命 | 中等 |
| TLS 证书 | `/var/lib/rancher/k3s/server/tls/` | 🔴 致命 | 需重签 |
| Token | `/var/lib/rancher/k3s/server/token` | 🟠 重要 | 影响节点加入 |
| Manifests | `/var/lib/rancher/k3s/server/manifests/` | 🟡 一般 | 可从 Git 恢复 |
| PV 数据 | 各存储后端 | 🔴 致命 | 依存储方案 |

---

## K3s 内置快照

K3s 内置了 etcd 自动快照功能：

```bash
# 启动参数中启用自动快照
curl -sfL https://get.k3s.io | INSTALL_K3S_EXEC="server \
  --cluster-init \
  --etcd-snapshot-schedule-cron '0 */6 * * *' \
  --etcd-snapshot-retention 10 \
  --etcd-snapshot-dir /backup/etcd-snapshots \
  ..." sh -
```

| 参数 | 说明 |
|------|------|
| `--etcd-snapshot-schedule-cron` | 快照调度 cron 表达式（示例：每 6 小时） |
| `--etcd-snapshot-retention` | 保留快照数量 |
| `--etcd-snapshot-dir` | 快照存储路径（建议挂载外部存储） |

**手动触发快照：**

```bash
k3s etcd-snapshot save --name pre-upgrade-$(date +%Y%m%d)
```

## 灾难恢复流程

<Callout type="warn" title="灾难恢复前须知">
  以下流程会**重置集群状态**到快照时刻。在快照之后创建或修改的资源将丢失。执行前务必确认快照版本。
</Callout>

<Steps>
  <Step>
    ### 停止所有 Master 上的 K3s 服务
    ```bash
    # 在所有 Master 节点执行
    systemctl stop k3s
    ```
  </Step>
  <Step>
    ### 在第一个 Master 上恢复快照
    ```bash
    k3s server \
      --cluster-reset \
      --cluster-reset-restore-path=/backup/etcd-snapshots/pre-upgrade-20260307
    ```
    此命令会从快照恢复 etcd 数据并重新初始化集群。
  </Step>
  <Step>
    ### 启动第一个 Master
    ```bash
    systemctl start k3s
    
    # 验证集群状态
    kubectl get nodes
    kubectl get pods -A
    ```
  </Step>
  <Step>
    ### 重新加入其他 Master（HA 模式）
    ```bash
    # 先清理旧数据
    rm -rf /var/lib/rancher/k3s/server/db/
    
    # 重新加入
    systemctl start k3s
    ```
  </Step>
  <Step>
    ### 验证 Worker / Edge 节点自动重连
    Worker 和 Edge 节点通常会自动重连。如未自动恢复，重启 k3s-agent 服务：
    ```bash
    systemctl restart k3s-agent
    ```
  </Step>
</Steps>

## 自动化备份脚本

```bash
#!/bin/bash
# k3s-backup.sh — 建议通过 cron 每日运行
set -euo pipefail

BACKUP_DIR="/backup/k3s/$(date +%Y%m%d-%H%M%S)"
mkdir -p "$BACKUP_DIR"

# 1) etcd 快照
k3s etcd-snapshot save --name "daily-$(date +%Y%m%d)" 2>/dev/null || true

# 2) 关键目录备份
cp -r /var/lib/rancher/k3s/server/tls    "$BACKUP_DIR/tls"
cp    /var/lib/rancher/k3s/server/token   "$BACKUP_DIR/token"
cp -r /var/lib/rancher/k3s/server/manifests "$BACKUP_DIR/manifests" 2>/dev/null || true

# 3) 同步到远端存储
rsync -az "$BACKUP_DIR" backup-server:/archive/k3s/ 2>/dev/null || \
  echo "⚠️  远端同步失败，请检查网络"

echo "✅ 备份完成: $BACKUP_DIR"
```

<Callout type="info" title="3-2-1 备份原则">
  至少保留 **3 份**备份副本，存储在 **2 种**不同介质上，其中 **1 份**位于异地。K3s etcd 快照 + 本地磁盘 + rsync 远端满足此原则。
</Callout>

# API 接口参考

**MSRU | QMS** 采用“API 优先（API-First）”的研发架构。系统的每一项核心功能，从质量标准定义到 SPC 数据分析，均通过标准化的 RESTful 接口对外暴露。

本参考文档旨在协助第三方系统（如自建 MES、PLM 或供应商 Portal）实现与 MSRU 质量引擎的深度集成。

<Callout type="info" title="设计原则：资源导向">
  我们的 API 设计遵循 HATEOAS 原则。所有的质量实体（Inspection Plan, Task, Violation）均被视为唯一的资源路径，支持标准的状态机转换。
</Callout>

## 1. 认证与安全机制 (Authentication)

为了保障工业生产数据的机密性与完整性，所有 API 请求必须通过 **mTLS + JWT** 的双重验证。

<Tabs items={['认证流程', 'Header 规范', '错误编码']}>
<Tab value="认证流程">
1. **客户端证书申请**：从 MSRU 控制台下载边缘节点专有的 `.crt` 文件。
2. **凭证交换**：使用 client_id 与证书交换临时 Access Token。
3. **请求携带**：在 HTTP Header 中注入 `Authorization: Bearer <TOKEN>`。
</Tab>
<Tab value="Header 规范">
| 键名 | 模式 | 说明 |
| :--- | :--- | :--- |
| `X-MSRU-Site-ID` | 必选 | 当前操作所属的物理工厂标识。 |
| `X-MSRU-Trace-ID` | 建议 | 用于全链路分布式追踪，便于排障。 |
| `Content-Type` | `application/json` | 数据交换统一采用 JSON 格式。 |
</Tab>
<Tab value="错误编码">
- **401**: Token 过期或证书无效。
- **403**: 权限不足（如质检员尝试调用删除标准接口）。
- **422**: 业务逻辑校验失败（如录入值超出物理合理范围限制）。
</Tab>
</Tabs>

## 4. 性能与限流 (Throttling)

由于 QMS 涉及高频的 IoT 采集，我们在边缘节点设置了动态限流门限。

<MathEquation 
  inline={false} 
  formula={String.raw`Limit_{rate} = \begin{cases} 1000 \text{ req/s} & \text{(Intranet/Edge Agent)} \\ 60 \text{ req/s} & \text{(Public Cloud API)} \end{cases}`} 
/>

这种分层限流确保了核心生产控制逻辑始终拥有最高优先级，而报表同步等非实时请求不会挤占带宽。
